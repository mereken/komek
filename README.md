# Komek: маркетплейс бытовых поручений в Алматы

Веб-приложение, где одни публикуют небольшие поручения (забрать посылку, постоять в очереди, выгулять собаку), а другие откликаются и выполняют их за деньги. Рассчитано на телефон: запускаем на ноутбуке, показываем на телефоне.

**Стек:** Spring Boot 3 (Java 17) · PostgreSQL 16 · React 18 + TypeScript

## Возможности

- **Для всех:** регистрация по телефону или e-mail с кодом, вход, профиль с рейтингом, переключатель режима «Заказчик / Исполнитель».
- **Заказчик:** создать заказ, смотреть отклики, выбрать исполнителя, отменить заказ, оценить исполнителя.
- **Исполнитель:** лента заданий с поиском и фильтром, отклик со своей ценой, «Начать» и «Завершить» задание.

Свой заказ в своей ленте не виден, поэтому для проверки нужны **два аккаунта**.

## Запуск

Нужны: JDK 17+, Maven, Node.js 18+, Docker Desktop.

Порядок всегда такой: **база → бэкенд → сайт**.

**1. База.** Запусти Docker Desktop, затем в корне проекта:
```powershell
docker compose up -d
```
Проверка: `docker ps` показывает контейнер `komek-db`.

**2. Бэкенд.**
```powershell
cd backend
mvn spring-boot:run
```
Готов, когда в консоли есть `Started KomekApplication`.

**3. Сайт** (в новом окне терминала).
```powershell
cd frontend
npm install
npm run dev
```
Открой http://localhost:13000

Порты: сайт **13000**, API **18080**, база **15432** (выбраны редкие, чтобы не было конфликтов).

## Телефон

1. Телефон и ноутбук в одной Wi-Fi сети.
2. В консоли сайта выбери адрес `Network: http://...:13000/` своей Wi-Fi сети (адреса виртуальных адаптеров не подходят). Свой IP можно узнать через `ipconfig`.
3. На телефоне открой `http://<IP ноутбука>:13000` (именно `http`).

Не открывается? Разреши порт в брандмауэре (PowerShell от администратора):
```powershell
New-NetFirewallRule -DisplayName "Komek 13000" -Direction Inbound -Protocol TCP -LocalPort 13000 -Action Allow -Profile Any
```
Также проверь: сеть Windows «Частная», VPN выключен, в Wi-Fi нет изоляции устройств (общежитие, вуз, кафе). Запасной вариант: `ngrok http 13000`.

## Код подтверждения

SMS не подключены, поэтому код показывается на экране жёлтой плашкой и печатается в консоли бэкенда.

## Демонстрация

1. **Заказчик:** регистрация → «Создать заказ» → «Опубликовать».
2. **Исполнитель** (второй аккаунт, телефон или окно инкогнито): найти заказ в ленте → «Откликнуться».
3. **Заказчик:** «Заказы» → «Посмотреть отклики» → «Выбрать».
4. **Исполнитель:** «Задания» → «Начать выполнение» → «Завершить задание».
5. **Заказчик:** поставить оценку исполнителю.

## Посмотреть данные в базе

```powershell
docker exec -it komek-db psql -U komek -d komek
```
```sql
SELECT id, full_name, phone, email, mode FROM users;
SELECT id, title, status, reward, runner_id FROM tasks;
SELECT * FROM task_responses;
\q
```
Или через DBeaver / pgAdmin: host `localhost`, port `15432`, база, пользователь и пароль `komek`.

## Если что-то не работает

| Проблема | Решение |
|---|---|
| `Connection refused` к `localhost:15432` | База не запущена: открой Docker Desktop и выполни `docker compose up -d` |
| `password authentication failed` | Проверь `docker ps` и порт `15432` в `application.properties` |
| Ошибки про таблицы `users` или `email` | Осталась старая база: `docker compose down -v`, затем `docker compose up -d` |
| «Нет связи с сервером» в приложении | Бэкенд не запущен |
| `Port 13000 is already in use` | Закрой старый `npm run dev` |
| Телефон не открывает страницу | См. раздел «Телефон» |
| Заказ не виден в ленте | Нужен режим «Исполнитель» и чужой заказ с будущим сроком |

Сбросить все данные: `docker compose down -v`, затем `docker compose up -d`.
